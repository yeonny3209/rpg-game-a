## 2026-11-07 · 링크로 접속 (Cloudflare 터널, 기획자 요청)

| 주제 | 결정 |
|---|---|
| 방식 | 지금은 **내 PC 서버 + Cloudflare "빠른 터널"**(무료, 계정 없음): `tools\run-server.cmd` → `tools\run-tunnel.cmd`. 나온 `https://….trycloudflare.com` 주소를 친구에게 알려 주면 됨. 24시간 서버(Oracle 무료 ARM)는 스테이지 4(원격 테스트) 때 이어서 준비 |

| 보안 | 로그인이 **닉네임만**이라 링크를 아는 사람은 누구든 아무 닉네임으로 들어올 수 있음(실제 계정은 지인 서비스 전에 만들기로 한 것). 링크를 공개된 곳에 올리지 말 것. **관리자 개발 명령은 "관리자 닉네임 + 이 PC에서 접속"일 때만** 작동 — 터널로 들어온 접속은 `CF-Connecting-IP`의 실제 주소가 보이므로 관리자 닉네임을 써도 거부됨 |
| 받은 파일 | `tools/cloudflared/cloudflared.exe` (Cloudflare 공식 GitHub 릴리스, 55MB, git 제외) |

## 2026-11-07 · 비밀번호 로그인 (기획자 요청: 링크에서도 관리자 명령 + 비밀번호)

| 주제 | 결정 |
|---|---|
| 로그인 | 닉네임 + **비밀번호(4~32자)**. 새 계정은 로그인 화면의 **"계정 만들기"**로 비밀번호를 두 번 입력해서 만듦. 닉네임만으로 들어가던 방식은 없어짐. 프로토콜 v5 |
| 저장 | 비밀번호는 DB에 **PBKDF2-SHA256(12만 회, 계정마다 다른 소금)** 해시로만 저장(`accounts.password_hash`). 평문은 저장·기록 안 함, 브라우저에도 저장 안 함(닉네임만 기억) |
| 옛 계정 | 비밀번호가 생기기 전 계정(세윤 등)은 **서버 PC(localhost)에서 처음 접속할 때** 입력한 비밀번호가 그 계정의 비밀번호가 됨. 링크로는 못 가져감(낯선 사람이 먼저 가로채는 걸 막음) |
| 관리자 | 관리자 닉네임(`server_config.json`의 `admins`)은 **계정 만들기·처음 비밀번호 정하기를 서버 PC에서만** 가능. 그 뒤에는 **비밀번호만 맞으면 링크에서도 개발 명령을 쓸 수 있음** (이전의 "이 PC에서만" 제한은 없앰) |
| 무차별 대입 | 같은 접속 주소 또는 같은 닉네임에서 **5번 틀리면 5분 잠금**(서버 PC 자신은 안 잠김). 터널로 들어온 접속의 실제 주소는 `CF-Connecting-IP`로 구분하되, 서버 PC에서 온 접속일 때만 그 헤더를 믿음(다른 컴퓨터가 헤더를 위조 못 하게) |
